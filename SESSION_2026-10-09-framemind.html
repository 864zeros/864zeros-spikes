Session Continuity Snapshot: FrameMind Spike & On-Edge SLM Fleet Architecture

Date: 2026-10-09 • Topic: framemind • Spike Fleet: 864zeros-spikes

State at Start: GemmaEdge spike completed and deployed on GitHub Pages. FrameMind existed only as a raw concept markdown file.

State at End: FrameMind Tier 1 spike fully architected, implemented with 4 zero-dependency Feature Bricks, verified with automated test suite, accompanied by a Google Colab LoRA training pipeline, published in a live interactive dual-viewport testbed, and committed/pushed to GitHub with an accepted Architectural Decision Record (ADR) on Hybrid Mobile Wrappers and an updated Spikes Backlog.

1. What Was Built

Feature Bricks (FrameMind/src/bricks/)

  • collector-audio-brick.js: Ingests speech events, acoustic dB energy, silence, and tags. Maintains 10s rolling temporal window.
  • slm-cinematography-brick.js: Base Gemma 256d vectorizer with dynamic LoRA adapter hot-swapping in 0.047 ms across Podcast, Fitness, and Keynote adapters.
  • director-brick.js: Intent engine classifying audio trajectories against 6 cinematographic prototypes in 0.30 ms.
  • framing-mutator-brick.js: 60fps cubic-bezier camera transitions and safe 9:16 vertical crop rendering on HTML5 Canvas.
  • inspector-brick.js: Telemetry logger asserting strictly 0 bytes network egress.

Showcase Portal & Testbed (FrameMind/index.html)

Multi-tab interactive portal featuring dual-viewport procedural studio visualizer, ASR ticker, LoRA selector, telemetry HUD, architectural report, and Colab launcher.

Verification & LoRA Pipeline

  • tests/test-framemind.js: Automated test suite passing 100% of brick assertions.
  • notebooks/Train_FrameMind_LoRA.ipynb: 1-click free Google Colab notebook for training ~3.1 MB LoRA adapters.
  • notebooks/synthetic_framing_dataset.json: Contrastive training pairs.

2. Decision Record

  • Decision 1: Browser-First Web/Canvas Testbed (Tier 1) Before Native Android (Tier 2): Allowed instant verification of mathematical framing logic with zero compilation delay on Windows.
  • Decision 2: Local Asset Bundling as Accepted Mobile Production Option: Adopted ADR for local bundling inside Capacitor/WKWebView sandboxes with 0 cloud runtime dependencies.
  • Decision 3: Single Base SLM with Modular LoRA Adapter Hot-Swapping: Eliminated model bloat by swapping 3.1 MB adapters instead of shipping multi-gigabyte models.
